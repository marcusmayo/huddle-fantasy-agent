# Local draft continuity

This prepared local workspace keeps Huddle recommendations, reconciliation and decision history available when the hosted service disappears. It must be prepared **before the draft starts**. It does not rescue an already-running hosted draft by silently moving control, and it does not create an unattended computer-use runner.

Recording is optional external evidence documenting Huddle and ChatGPT computer use. This workspace has no recorder connection, recording health check or video prerequisite. Its display and audit serve the draft operator directly.

## Preparation and operation

1. Before entering the countdown, install matching Huddle source and locked dependencies on the local computer and hosted service. Freeze those files for the draft. Choose an unused loopback port and one persistent local state directory. Resolve any occupied port before the handoff; the supervisor never closes an unrelated service.
2. Finish hosted Yahoo account, league/settings, seat, player identity/depth and source-age readiness. Select the intended active Yahoo session with zero completed picks and no saved selection plan. Stop any existing controller. Read the actual Yahoo room while it is still waiting, confirming league/team/seat, zero completed picks, manual mode and Autodraft OFF.
3. Compute the local `codeIdentity()` exported by `src/services/draft-continuity.js`. Through the authenticated hosted Huddle client, call `localTransfer` with a stable UUID `transferId`, `expectedCodeIdentity`, `target: {instanceId: <another stable UUID>, origin: "http://127.0.0.1:<chosen port>"}`, and the fresh room `observation`. The client is `createHuddleDraftClient` in `scripts/live-draft-controller.mjs`; use the existing authenticated request transport. Do not extract browser credentials into a bundle.
4. Preserve the returned `bundle` as a local JSON file outside source control. A successful response means hosted control is now persistently fenced for that Yahoo league. If the response is lost, retry the **same transfer ID, session and target** to retrieve the same bundle. Do not create another transfer or assume a failed response means no handoff occurred. Changed local/hosted source, failed readiness, a started draft, active controller or prior selection plan are rejected before a new fence is saved.
5. Start `npm run draft:local -- --bundle <absolute prepared JSON path> --state-dir <absolute persistent directory>`. Run it as a supervised local process independent of an editor tab. If launching a background process on Windows, keep its window hidden. Preserve its process handle and logs so cleanup targets only this process.
6. Wait for the supervisor's `ready` record. Open its exact `url`, verify **LOCAL DRAFT**, the real league/team/seat, source date and reconciled board. Its `/health` record must match the transfer, local instance and code identity. The absence of a local Yahoo OAuth connection is expected: Yahoo availability and Results are read through the browser adapter. The view labels that path “Yahoo through browser.”
7. Bind the controller's Huddle client and protected Huddle role to this exact local origin; keep the real Yahoo draft-room role. Reconcile the fresh Yahoo board, verify prepared preferred/fallback identities, accept the execution handoff and activate control while Yahoo is still waiting. Readiness and an open page do not themselves start the controller. A fresh matching browser observation keeps the local feed current; stale, wrong-board, wrong-room or expired-controller observations cannot do so.
8. During the draft, keep invoking the maintained computer-use controller in bounded, awaited windows. Every selection still needs the current displayed recommendation/decision, a saved dispatch intent, one browser input and Yahoo-result reconciliation. A hosted outage no longer affects these local app requests. Yahoo/browser/internet availability and an actively invoking operator are still required.

There is deliberately no automatic return of execution to the hosted instance. The local bundle authorizes one identified loopback origin on the prepared computer. Do not copy it to another computer and run a second executor. Hashes detect corruption and differing source; they are not signatures or protection against a privileged user deliberately altering state or running duplicate copies. The hosted fence must remain durably stored; restoring a pre-transfer hosted backup during execution is unsupported.

## Recovery and durable history

The local server binds only its prepared `127.0.0.1` port and serves the compact view plus the prepared session's workspace, controller, decision, health-review, browser-result and audit routes. It cannot create/delete/reopen sessions or change leagues. JSON writes reject a different Origin; host validation rejects unexpected hostnames. No OAuth or provider client is created. The copied pool contains normalized ranking evidence and retains its original date; copying or restarting cannot refresh it.

`scripts/local-draft-supervisor.cjs` owns one worker and an exclusive state-directory lock. Three failed health probes terminate only that worker. A replacement starts only after the old process's exit/close is observed. Startup and repeated failures are bounded and logged in `supervisor-events.jsonl`. An occupied port is left alone. The server exits if its supervisor disconnects. The supervisor itself is not an operating-system boot service; computer shutdown, sleep and supervisor failure still require recovery by the operator or separately accepted process management.

Each accepted result and decision event is atomically saved to `draft-state.json`. On restart, the same prepared bundle must match the saved local state and current code. An old controller lease is never restored. Re-read Yahoo and establish a fresh handoff. A saved `submit-started` event without a reconciled result blocks new control: a restart is not evidence that no input happened. In particular, the new process cannot authenticate the old run's claim that it issued no input. Preserve that uncertainty and reconcile Yahoo; do not clear the event to retry.

An existing workspace may reopen with older cached data so evidence is recoverable; the date stays visible and data older than 36 hours is flagged. A **new** workspace cannot be prepared/imported with undated, future-dated, incomplete or over-age data. This cache is not a source refresh or a substitute for current injury and availability observations.

After all picks reconcile, export `audit()` from the local client. Restore the hosted app's read path and independently reconcile its full Yahoo board. Call the hosted client's `localCompletion({transferId, audit})`. It requires a complete matching local history extending the original transferred hash chain, the expected draft length, and the same accepted identities/ownership at every hosted pick. Identical imports are idempotent; conflicting imports fail. The completion is attached as separate execution evidence. It does not rewrite hosted picks as historical Huddle choices, and it does not remove the execution fence.

## Verification scope

The automated continuity tests run actual local HTTP and `JsonStateStore` with a synthetic six-team DR room and injected clock. They exercise all 20 owned turns / 120 results after shutting down the hosted HTTP service, restart the local server halfway through, verify durable intent before every input, reconcile acceptance and attach completion only after an independent hosted board import. The simulated display adapter is not browser acceptance.

Separate tests launch real child Node servers, terminate one, deliberately freeze another using a test-only preload, and verify recovery at the same port without resurrecting a controller lease. Other cases cover a port owned by another service, bounded launch failures, matching source before transfer, failed-save rollback, retry conflicts, stale/bad bundles, unsafe targets, wrong local instances/display origins, route isolation and pending-submission recovery.

A subsequent CUA browser inspection verified the actual local display at 640×720 with preferred/safer/upside choices, the planned selection, 119 reconciled results and all 19 owned picks. Completion retained 120/120 and all 20 owned picks. It exposed and corrected a local-feed check that still expected the hosted poller. A regression now requires fresh, matching controller observations instead. The browser fixture supplied synthetic observations; it made no Yahoo input and no video. Temporary UI processes/tabs were closed and the viewport override reset.

Evidence outside the app repository: `draft-day/local-continuity-replay.json`, `local-continuity-process-tests/`, `local-continuity-browser-qa.json` and `local-continuity-remediation.json`. The final checkpoint records test counts, source/log hashes and the local commit. These repairs are not deployed or accepted against a new real Yahoo draft. Uninterrupted CUA invocation, actual Yahoo selector/queue behavior, production timing, source coverage/calibration and deployed-version acceptance remain open.
