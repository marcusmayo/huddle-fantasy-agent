# Next solution to the Yahoo mock admission gate

Status: proposed; no implementation or additional run is authorized by this document alone.

## Decision and current position

Keep the working immediate-drain change, but do not certify it as the timing solution. The last short run proved pending-frame dispatch resumes within 2 ms. Recognition API calls still took approximately 1.2 seconds, and queued age pushed samples beyond freshness limits. Huddle updated its recommendation, but the owned turn never obtained verified clock delivery. The post-update layout also overflowed. Both synthetic results reconciled; that is not manual-selection success.

The last candidate passed 462 tests across 59 files. Those results are a baseline, not acceptance of a future modified build. Full Yahoo mock admission also still depends on independent execution continuity, full controlled timing/visibility, editor-disconnected operation, recovery and ordinary report retrieval. Clock fixes alone cannot close the gate.

## 1. Disposition execution continuity before expensive validation

Review the existing selector lifecycle evidence and identify whether a concrete supported mechanism can sustain ChatGPT computer-use selection across every turn without another user prompt. Do not repeat broad capability searches or treat an automation reminder as a continuous selector. No extension, hidden Yahoo writes, credential extraction or human substitution is part of this plan.

If no supported candidate exists, explicitly retain the ChatGPT-operated Yahoo mock gate as blocked. Independent Huddle recommendation work can proceed, but cannot be presented as resolving autonomous selection. Return that limitation at the first checkpoint before spending time on full controlled drafts. A human-operated Yahoo validation is a separate scope decision requiring the user's explicit approval.

## 2. Isolate and reduce the remaining processing cost

Correct the timing labels first. The current `workerMs` wraps canvas conversion, FileReader loading, transfer, worker scheduling and OCR; local dependency code confirms conversion occurs before actual worker dispatch. It is not pure OCR time.

Measure the same saved image and live capture dimensions in the same visible browser layout, with warm-up separated. Capture separate timings for snapshot, conversion to encoded bytes, recognition of already encoded bytes, queue age, upload, server acknowledgment and visible receipt. Use supported library inputs; if true worker-local computation timing is unavailable, report that remaining uncertainty explicitly.

Run a bounded comparison: current canvas input versus explicit encoded-byte input, with at most one additional supported encoding option if the first comparison identifies conversion as material. Measure instrumentation-on/off overhead with the same image workload. Verify exact room, countdown, round and owner parsing against the three saved Yahoo headers, long opponent labels and ambiguous-text cases. Never select the fastest option if it loses required identity or timing accuracy.

Choose the implementation only from those results. If conversion dominates, remove or replace the expensive conversion boundary. If recognition or scheduling dominates, address that measured stage rather than adding queues or workers speculatively. Preserve two-times text resolution unless an alternative passes the complete image cases. Do not use a desktop benchmark as proof of browser performance.

Checkpoint: publish the latency breakdown and selected path before any full draft. If none of the bounded alternatives fits the freshness budget, stop clock certification and present an architecture or scope decision instead of launching more drafts.

## 3. Make frame admission account for unfinished work

Retain one in-flight image and one replaceable pending image. At dispatch, compare original capture age plus a conservative recent processing estimate plus delivery reserve against the existing freshness budget. Separate discovery and compact processing estimates; use conservative warm-up behavior and react to slow outliers. Estimates are a scheduling filter, never evidence that a frame is fresh.

Discard a frame unlikely to finish fresh and wait for the newest eligible capture; do not retimestamp it, refresh frozen pixels, relax the server's 1,500 ms freshness/continuity limit or reduce the human reserve. Preserve actual downstream age checks regardless of the estimate. If discarding causes continuity starvation, report it as a failed throughput gate rather than counting discarded frames as successful samples.

Test delayed workers, sparse callbacks, slow uploads, resize/disconnect, wrong-room recovery, periodic discovery and owned/opponent transitions. Replay the failed trace to show that its original delays still fail honestly, then verify the corrected sequence meets the same limits.

## 4. Fix dynamic visibility and ordinary evidence retrieval

Set the viewport contract from the user's actual split-screen arrangement. Lay out the current recommendation, every recommendation alternative, latest reconciliation and all owned picks readably as the board grows. Reduce nonessential chrome and use compact columns; do not clip required content or depend on manual mid-turn zoom. Test first, middle, consecutive-owned, final and completed states with long text, warning banners and 15 owned picks. Full draft history remains available through history/report; do not silently redefine that as only one recommended pick per turn.

Preflight must evaluate the post-update and maximum-content states, not only an empty board. If the viewport is too small, provide the required minimum size before the timer starts. A test that starts fitting and later overflows fails.

Reproduce normal partial/completed/post-restart report downloads through the visible browser route while Huddle stays open. Confirm request arrival, browser outcome, actual artifact creation, checksums and summary/CSV/JSON agreement. The host-side report retrieval from the failed run preserves diagnostic evidence but does not pass the browser-download gate. Do not disable browser protections or use alternate transport to declare that gate passed.

## 5. Freeze and validate one candidate in order

Clock length must not slow recommendations: a 70-second clock receives the same ASAP update target as a 30-second clock, leaving more human selection time. The ten-second requirement is a minimum, not permission to delay a recommendation until ten seconds remain.

Engineering targets before admission: steady processing/capture intervals and capture-to-server acceptance at most 1,000 ms, leaving headroom below the unchanged 1,500 ms hard limits. Report every outlier and maxima, not just medians. Initial discovery and periodic rediscovery remain in the evidence. A matched correct receipt and actual remaining reserve are the decisive delivery checks.

Earlier recovery evidence may be reused only with explicit build/path applicability; changes invalidate affected acceptance results. Do not automatically repeat unrelated checks after every small edit. Freeze before the full suite and full controlled runs.

## Stop and scope decision

Stop at the first required failure and produce its measured cause plus one bounded next correction. Do not repeat full drafts to gather another instance of a known failure. If selector continuity has no supported solution, or the browser pipeline cannot meet the unchanged clock budget, say which Yahoo admission requirement is infeasible under the current architecture. Keep Huddle's independent recommendation capability and its unverified clock status distinct. Dropping automatic clock certification or changing who selects requires a separate user decision; neither is silently substituted.
