# Draft improvements since the first real Yahoo draft

This is the current publication index. Older plans and failed-run reports remain historical evidence; their status statements do not override the results below. The [file inventory](draft-enhancement-file-inventory.md) lists the implementation, tests and reports, including previously unpublished work.

## Baseline and latest result

The September 8 real draft used **Astra at Extra High effort, computer use and external screen recording**, as confirmed by the user. Of twenty roster selections, the user submitted Jahmyr Gibbs after the assistant failed to activate execution; the assistant submitted eighteen, and Yahoo automatically selected Baltimore defense. The recorded review identifies five audibles, three outage fallbacks, two stale cards and one missed deadline. Yahoo graded Blitzkrieg C− versus the supplied top grade B+. These are historical facts from the [real-draft review](media/real-draft-previews.md), not reconstructed hidden model reasoning.

The latest actual Yahoo mock, room 11197752, completed with **15/15 manually verified owned picks, zero autodrafts and 120/120 results reconciled**. Every selection followed Huddle. The [results report](yahoo-desktop-mock-results-2026-09-10.md) and [compact public evidence](yahoo-mock-11197752-evidence.json) retain each selected ID, reason and measured cycle. This was an eight-team, half-PPR, 30-second mock, not the original six-team, twenty-round custom league.

The successful mock used the existing signed-in Edge session and the frozen browser-assisted controller. It does **not** validate every newer runtime feature. In particular, it did not establish independent Yahoo API delivery, clock OCR, API-agent continuity, verified compact-view display receipts, or repeated reliability. No new video was recorded for this mock.

## Scoring review: what changed and what did not

League-aware legal-lineup contribution, diminishing redundant bench value, owned bye coverage, QB reserve and late offensive-lineup completion were already present before the first real draft. They are included in the GitHub integration because `main` was behind the working branch, but are **not new fixes caused by that real draft**. See [the pre-draft retrospective](draft-final-postmortem-2026-09-08.md).

After the real draft, a reproducible benchmark compared the frozen repaired scorer, constrained ADP, constrained projection and an experimental two-pick look-ahead policy across 360 synthetic drafts. The candidate lost 0.587% on held-out average and regressed in four groups; it was rejected. **The look-ahead policy was not enabled and scoring weights were not tuned to imitate Yahoo's undisclosed grade formula.** The existing waiting-risk explanation now states that it is an uncalibrated heuristic. Source/health/projection evidence repairs remain material because scoring cannot compensate for stale or incompatible inputs. See [scoring benchmark](draft-scoring-benchmark.md).

## Experiments retained separately from the product

- **Read-only extension:** retained in `extensions/huddle-read-only` as development evidence. Withdrawn from the product direction; production companion routes remain disabled. Do not install it as a prerequisite for Huddle.
- **External API selector:** isolated model/browser loop, ordered response/call identities, exact controls, duplicate-input stops, verified completion and cumulative budget reservations. Short real-Huddle tests with synthetic clocks completed two owned turns at 30/70 seconds. Google rejected authentication in its isolated Yahoo browser, so it did not run the successful Yahoo mock. The files under `scripts/experiments` are opt-in, Windows-oriented validation tools, not app startup code; several require the original bundled Playwright runtime. They read a locally configured key only when explicitly invoked. See [API execution record](api-agent-test-execution.md).
- **WebSocket model transport and alternate clients:** ranked fallback plans, not demonstrated or enabled fixes. No unsupported background continuation of desktop browser tools is claimed.
- **Recording/media:** stays outside Huddle. Published videos and captions remain the separately edited historical evidence on `main`; original recordings, keys, browser profiles and raw operational artifacts stay outside Git.

## Acceptance and remaining limitations

The user's requested Yahoo completion condition was achieved for one desktop mock: all selections manual and all results reconciled. Observed selection cycles took 2.132–3.216 seconds; the conservative sampled-clock reserve estimate was at least 11.387 seconds. These are not turn-start-to-visible recommendation measurements. Some cycles started after substantial desktop handoff delay.

Still unproven: independent Yahoo mock publication/deadline delivery, sustained independent authenticated API selection, actual-Yahoo clock/display receipts, recovery under live interruption, and repeatability. The compact practice view in the successful run reported zero verified timely display receipts. Historical failures remain published so the later success does not erase them. Do not describe this publication as production certification or a guarantee of a clean future draft.
